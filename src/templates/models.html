🩹 Restauration ×2 (SeedVR2 — diffusion, détails fidèles)

Contrairement à un simple agrandissement, SeedVR2 reconstruit la matière (grain de peau, tissus, texte sur les panneaux) et double la résolution d'une image existante (ex. 1024×1024 → 2048×2048). Deux fichiers (~6,8 Go au total) : le modèle de restauration int8 et le VAE FP16. Une fois installé, le bouton « 🩹 Restaurer ×2 » apparaît sur chaque image et dans l'historique. Expérimental — exige ~10 Go de VRAM (fonctionne aussi en offload CPU, plus lentement).

⬆️ PiD (NVIDIA Pixel Diffusion — super-résolution générative ×4, 1024→4096)

Contrairement à RealESRGAN (lissage) ou SeedVR2 (restauration ×2), PiD ré-encode l'image avec le VAE de son backbone puis la décode directement en pixels 4096×4096, en seulement 4 étapes, conditionnée par le prompt de l'image (repris automatiquement depuis l'historique). Idéal pour recréer de la matière crédible : peau, tissu, texte, végétation. Backbones : FLUX.1, FLUX.2, Qwen-Image (int8_convrot, ~1,6 Go chacun). Socle commun : encodeur Gemma 2 2B bf16 (~5,4 Go) + tokenizer (~18 Mo) — dépôts non-gated (Comfy-Org/PixelDiT + unsloth/gemma-2-2b-it), aucun compte Google requis.
⚠️ Licence NSCLv1 : recherche / évaluation non-commerciale uniquement. Requiert le binaire sd-cli ≥ 2026-05-31. Une fois installé, le bouton « ⬆️ PiD ×4 » apparaît sur chaque image et dans l'historique (sortie 4096×4096).
Note : pour Qwen-Image 2.1 (latents 64 canaux), préférez 🩹 SeedVR2.

🧠 Légendeurs d'image (image → prompt, VLM local)

Un VLM local lit l'image et rédige le prompt qui permettrait de la reproduire — parfait pour une image qu'on a trouvée (bouton « 🔎 Image → Prompt » sur Générer / Édition), ou pour pré-remplir le prompt de ⬆️ PiD (bouton « 🧠 Décrire l'image » dans la modale PiD). Aucune donnée ne part sur internet après le téléchargement des poids. La description reste toujours éditable avant envoi — rien n'est lancé d'office.

📦 llama.cpp (requis par les légendeurs)

Uniquement la version officielle de github.com/ggml-org/llama.cpp — dernière release, build Windows CUDA (repli avx2/CPU). C'est le runtime de llama-mtmd-cli, l'exécutable qui légende les images.

🎭 Visage fidèle (PuLID) (arch FLUX — conserver le visage d'une photo)

PuLID injecte l'empreinte du visage d'une photo de référence dans la génération sans toucher au reste de l'image (contrairement à une LoRA d'identité). Fonctionne avec FLUX.1 Schnell, FLUX.1 Dev et FLUX.1 FHDR (et uniquement eux pour l'instant dans sd-cli). Il faut : (1) les poids PuLID (~1,14 Go) ci-dessous, (2) une empreinte d'identité par portrait (fichier .pulidembd, créée une fois avec scripts/pulid_extract_id.py — pile PyTorch externe requise), puis (3) choisir le portrait dans la section « ✨ Qualité → 🎭 Visage fidèle ».
